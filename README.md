# 抖音 / 小红书 线程撕裂者

> **本仓库已拆分为以下两个仓库，此后不再更新：**
> - 抖音：[KurisuRakko/Douyin-Thread-Ripper](https://github.com/KurisuRakko/Douyin-Thread-Ripper)
> - 小红书：[KurisuRakko/XHS-Thread-Ripper](https://github.com/KurisuRakko/XHS-Thread-Ripper)

适用于桌面浏览器的抖音、小红书网页版用户脚本（Tampermonkey / Violentmonkey），用于在海外网络环境下加快视频与图片加载。设计思路参考
[Bilibili 线程撕裂者](https://github.com/MrTangLuyao/Bilibili-thread-ripper)（多连接、多节点并发下载），代码针对这两个站点独立实现。

**本脚本不修改站点播放器代码**，仅执行以下三项操作：替换视频与图片地址、预加载、在站点接口数据中选择最高画质。
任一环节出现异常时均回退至站点原始地址，此时行为与未安装脚本一致。

## 实测效果（澳大利亚家庭宽带，2026-10-03）

| 场景 | 未安装 | 已安装 |
| --- | --- | --- |
| 抖音同一视频文件的下载速度 | 单连接约 9 Mbps | 多节点并发 200 Mbps 以上（64 MB 的 1080p 视频耗时 1.5–2.5 秒） |
| 抖音画质（未登录） | 默认 720p | 自动切换至接口提供的最高档位（多数为 1080p） |
| 切换至下一条视频 | 每条视频在切换后开始加载 | 预加载后续 2 条视频，切换后即时播放 |
| 小红书向下滚动一屏后，新封面全部显示所需时间 | 中位数约 1000 ms | 中位数约 90 ms |

## 安装

1. 在 Chrome 中安装 [Tampermonkey](https://www.tampermonkey.net/) 或 [Violentmonkey](https://violentmonkey.github.io/)。
2. **Chrome 必需步骤**：打开 `chrome://extensions`，进入 Tampermonkey（或 Violentmonkey）的「详情」页，启用 **「允许运行用户脚本」**（旧版 Chrome 需启用右上角的「开发者模式」）。未启用时脚本不会运行。
3. 两个站点各对应一个脚本，按需安装：
   - 抖音：[**douyin.user.js**](https://raw.githubusercontent.com/KurisuRakko/DouyinXHS-Thread-Ripper/main/user_scripts/douyin.user.js)
   - 小红书：[**xhs.user.js**](https://raw.githubusercontent.com/KurisuRakko/DouyinXHS-Thread-Ripper/main/user_scripts/xhs.user.js)

   如已安装旧版 `dxtr.user.js`，请先在脚本管理器中将其卸载，再安装本脚本。
4. 打开抖音或小红书网页版，页面右下角显示 **DX** 悬浮按钮即表示脚本已运行。点击该按钮可打开设置面板。

发布新版本后，Tampermonkey 将自动更新脚本。

## 设置

| 选项 | 默认值 | 说明 |
| --- | --- | --- |
| 总开关 | 开启 | 关闭后脚本不执行任何操作 |
| 视频多线程 + 秒开 | 开启 | 从多个 CDN 节点并发下载视频，并预加载后续视频 |
| 自动最高画质 | 开启 | 仅在站点接口提供的画质中选择最高档位，不绕过任何权限限制 |
| 净化页面（抖音） | 开启 | 以贴靠左侧的精简图标栏（搜索 / 推荐 / 关注 / 我的，底部为通知 / 消息 / 头像）替代左侧导航栏与顶栏；打开首页或「精选」页时直接进入推荐页（每个标签页仅跳转一次） |
| 图片换最快节点（小红书） | 开启 | 按实测速度选择图片节点；加载超时的图片向次优节点补发请求 |
| 并发线程 | 自动 | 自动模式下在 4–24 之间选取吞吐量最高的数值；设备性能较低时可手动设为 4 或 8 |
| 预加载后面几条 | 2 | 设为 0 时不预加载；大于 40 MB 的视频不预加载 |
| 内存缓存上限 | 300 MB | 已下载的视频保存在内存中，超出上限时优先清除最久未播放的视频 |

- 设置更改将在页面刷新后生效。
- 隐藏悬浮球后，可按 **Alt+Shift+D** 重新显示。
- 「复制诊断信息」将复制一份 JSON 报告（包括节点速度、下载记录和最近日志），反馈问题时请附上；也可在浏览器控制台执行 `copy(__dxtrDebug.report())` 获取。诊断信息不含 Cookie，但视频地址带有签名，公开发布前请自行检查。

## 工作原理

### 视频

两个站点的网页视频均为完整 MP4 文件（而非 Bilibili 所用的分段 DASH），每个视频的接口数据中包含 2–3 个不同 CDN 节点的地址。

- **多线程下载**：将文件切分为 0.25–2 MB 的分块，同时从多个节点并发下载；实时测量各节点速度，较慢的节点分配较少分块，出错的节点停止使用；
  单个连接停滞超过 4 秒即断开，剩余部分从已接收位置起改由其他节点续传；下载接近完成时，将最慢分块的后半段分配给空闲连接（work stealing）。
  每个分块均校验 `Content-Range` 或长度，校验不通过的数据予以丢弃。
- **接管方式（不修改播放器）**：
  - 播放器直接为 `<video>` 设置 MP4 地址时：若该视频已下载完成，则将地址替换为内存中的 `blob:` 副本（即时播放，拖动进度正常）；
    若尚未下载完成，则仍使用原地址播放，同时在后台并发下载；原生加载速度不足（播放停滞或缓冲即将耗尽）时，在同一时间点无缝切换至副本。
    播放器读取 `src` / `currentSrc` 时返回的仍为原地址。
  - 播放器通过 MediaSource 分段请求数据时（抖音的 DASH 模式、部分小红书视频）：首次请求照常经由网络完成，同时在后台并发下载完整文件；
    此后播放器请求的分段若已存在于内存中，则直接从内存返回。
- **切换后即时播放**：当前视频开始播放后，按接口返回的顺序预加载后续 2 条视频。
- **最高画质**：抖音接口的 `bit_rate[]` 字段列出全部档位，脚本将其中最高的 MP4 档位写入 `play_addr`，并仅向 DASH 播放器保留最高档位；
  小红书则将每个编码列表中画质最高的条目调整至首位。

### 小红书图片

笔记图片的地址格式为 `sns-webpic-*.xhscdn.com/<时间>/<签名>/<图片ID>!<样式>`。同一 `<图片ID>!<样式>` 亦可从其他十余个图片节点获取，**返回的字节完全相同**（经实测，同一图片的大小与格式一致）；但从海外访问时各节点速度差异显著，且与用户所在网络相关。因此脚本执行以下处理：

1. 页面打开时，使用一张已显示的图片对所有节点进行一次并发测速；此后依据页面上每张图片的实际加载时间（Resource Timing）持续更新评分；
2. 新图片请求分配给当前速度最快且在途请求较少的节点（并以较低频率试用其他节点，以保持排名准确）；
3. 图片在短时间内仍未加载完成时，同时向次优节点补发请求，采用先返回的结果；
4. 节点出错时回退至原始地址；
5. 接口返回的下一页封面以及当前打开笔记的全部图片，均在后台预加载。

## 不执行的操作

- 不绕过登录、会员、地区、清晰度、审核或任何签名限制；仅使用站点已向当前用户提供的地址和画质。
- 不上传任何数据，不含遥测；下载内容仅保存在当前页面的内存中。
- 不支持移动设备（用户脚本仅适用于桌面浏览器）。

## 已知限制

- 大于 200 MB 的视频不予接管，由站点原生加载。
- 不处理直播。
- 未登录时，抖音首页推荐流会跳转至「精选」页；登录后的推荐流中，切换后即时播放的效果最为明显。
- 站点改版（接口字段、播放器结构变更）可能导致部分功能失效；失效时回退至原生加载，不影响视频正常播放。

## 开发

项目无外部依赖，安装 Node.js 即可构建和测试。

```text
src/core/      下载内核（分块、调度、多节点）、视频缓存、fetch/XHR 钩子、<video> 地址钩子
src/sites/     douyin.js、xhs.js（视频数据）、douyin-images.js（图集预加载）、xhs-images.js（图片节点）
src/ui/        设置面板（Shadow DOM，样式仅使用 Rakko Design token）
scripts/       build.mjs（按站点分别构建两个用户脚本）、sync-design.sh（同步 vendor/rakko-design）
dev/           单元测试、CDP 端到端测试工具
vendor/        Rakko Design 第三方文件，仅由 scripts/sync-design.sh 生成，请勿手动修改
```

- 构建：`node scripts/build.mjs [版本号]`，输出 `user_scripts/douyin.user.js`、`user_scripts/xhs.user.js`
- 单元测试：`node dev/run-tests.js`
- 端到端测试（需本机运行已开启 CDP 9222 端口的 Chrome）：
  - `node dev/inject.mjs <网址> [秒数]`：根据网址选择对应站点的构建产物注入并打开页面，输出诊断报告；
  - `node dev/hit-test.mjs`、`node dev/feed-test.mjs`：测试抖音即时播放与切换至下一条视频；
  - `node dev/image-bench.mjs [轮数]`：小红书封面加载对比测试（启用与停用）；`node dev/note-bench.mjs <笔记网址…>`：笔记轮播图测试。
